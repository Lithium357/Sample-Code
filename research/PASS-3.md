# Research pass 3: language breadth and uncommon contracts

Active long-run user goal: approximately 2 billion good code tokens. The
operational metric is `cl100k_base` tokens in unique current source/support
files with passing source-bound execution checks. It excludes docs, prompts,
harnesses, logs, failed snapshots, archived duplicates and syntax-only results.
The target is not a license to pad or repeat examples. The goal remains active.

User steering adds all languages and niche/uncommon usages. Rotation continues
across the established languages and introduces others when executable tools
are available. No fixed list is claimed exhaustive. Planned breadth includes
managed, functional, scripting, systems and data/query languages, with exact
dialects/runtimes recorded per example. Planned coverage is not generated volume.

## Batch 1

All four passed locally. Python/Node/Go execute on the host; F# executes in the
managed .NET runtime via F# Interactive, labeled `managed_runtime`, not AOT
machine code. F# uses installed SDK libraries only, without NuGet packages.
SDK initialization/cache directories are owned scratch paths, and their
environment overrides are recorded alongside exact commands and versions.
CI adds Linux and Windows checks for Python/JavaScript/F#, plus the existing
Linux source-bound replay that includes the new Go unit.

Each new file has an embedded deterministic fixture suite. Tests include
literal expected values, identity/state invariants and independent reference
checks where useful; expected values are not generated by the tested helper.
The initial inventory of the F# example is an explicit valid-input precondition;
it does not claim validation of arbitrary caller-supplied maps. The JavaScript
adapter cannot interrupt a permanently blocked upstream next() call.

The visible prompts are in `provenance/research-pass-3.txt`, task ID
`research-pass-3`. Exact generation model version remains unknown. No benchmark

## Batch 2

C# `pooled_writer.cs` implements IBufferWriter<byte> and deterministic ownership
of pooled arrays. It caps logical capacity even for oversized physical rentals,
copies only initialized bytes on growth, preserves data if rental fails, clears
returned arrays and makes Dispose idempotent. Tests use a tracking pool, injected
rental failure, exact byte expectations and a MemoryStream reference across 64
capacities. The borrowed spans have an explicit expiration contract; this is
a single-owner API, not a thread-safe producer queue. The source compiles as
C# 12 for net10.0 with nullable checking and warnings as errors. The harness
creates an owned scratch project and uses an empty local package source;
generated project text and exact build/run commands are recorded as control
inputs, not additional training source tokens.

Python `deferred_sqlite.py` and its SQLite DDL support file test deferred foreign
keys at commit, nested RELEASE versus outer RELEASE, repair after failed commit,
usable nested savepoints after failure, rollback and immediate CHECK failures.
Each rejection checks the extended SQLite error code, transaction state and
rows. These are purpose-written fixtures; semantics were checked against
[SQLite's official documentation](https://www.sqlite.org/foreignkeys.html#fk_deferred).
The SQL support file is labeled `sql-sqlite` separately from its Python driver.
Both source hashes must match the passing bundle for either to count.

All six pass-3 units (seven source/support files) passed their local checks.
One unsuccessful C# invocation is retained: compilation succeeded, but an
inherited Platform=x64 environment moved the default output to bin/x64/Debug.
The runner guessed bin/Debug and could not launch the program. The harness now
sets --output explicitly. Source and test expectations were unchanged; the
successful rerun is linked to the original failure. CI broadens the C# checks
to both Windows and Linux and executes the new SQLite driver on both hosts.

## Batch 3

Tcl `versioned_patch.tcl` adds dictionary copy-on-write updates with optimistic
version checking and exact structured error codes. Values, spaces, command-like
text and embedded NULs remain data; production patch handling never evals them.
Tests cover valid-prefix rollback, malformed lists, stale/canonical versions,
missing/colliding keys, empty and maximum values, edit-count limits and exhausted
versions. It passed in the actual Tcl 8.6.12 interpreter embedded through Python
tkinter.Tcl; no Tk window/UI is created. The recorder can also use native tclsh
and records the exact CLI/version when it does so. CI installs Tcl on Linux and
exercises this case in the language-breadth matrix rather than assuming all
Python installations include Tcl/Tk support.
